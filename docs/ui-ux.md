# UI/UX 원칙

## 목적

이 문서는 소모임 운영진용 관리자 화면의 일관된 사용 경험을 위한 기준이다. 현재 사용자는 적고 관리 작업은 반복되므로, 화려한 화면보다 실수 예방과 작업 상태의 명확성을 우선한다.

## 반응형 기본 원칙

- 데스크톱과 모바일 모두 지원한다. 좁은 화면에서는 다열 레이아웃을 한 열로 전환한다.
- 모바일에서 모든 기능을 작은 모달에 넣지 않는다. 키보드가 열려도 입력 흐름이 유지되어야 한다.
- 주요 터치 대상은 최소 `44 × 44px`를 확보한다. 한 손 조작의 주 동작은 화면 하단 또는 엄지가 닿기 쉬운 영역에 둔다.
- 버튼과 입력 요소는 터치 가능한 크기를 확보하고, 위험 작업은 일반 작업과 시각적으로 구분한다.
- API 요청이 진행 중이면 공통 로딩 overlay와 해당 작업 버튼의 진행 상태를 함께 표시해, 처리 중인지 입력이 막힌 것인지 구분할 수 있게 한다. 실패 메시지는 해당 작업 화면 또는 Dialog 안에서 즉시 확인할 수 있어야 한다.
- 정보는 처음부터 모두 펼치지 않는다. 목록 → 빠른 확인/조치 → 상세/작성 순서의 Progressive Disclosure를 기본으로 한다.

## 모바일 화면 전환 규칙

| 작업 성격 | 모바일 기본 방식 | 원칙 |
| --- | --- | --- |
| 조회 및 빠른 액션 | Bottom Sheet | 목록을 유지한 채 핵심 정보와 짧은 조치만 제공한다. |
| 복잡한 상세 조회 | 별도 Page | 긴 이력, 여러 섹션, 상세 판단이 필요한 내용은 전용 페이지로 연다. |
| 신규 등록 / 수정 | 별도 Page | 키보드, 긴 폼, 검증 오류, 임시 입력값을 안정적으로 다룬다. |
| 삭제 / 탈퇴 / 정지 / 취소 | Dialog | 실행 전 대상·영향·되돌릴 수 없는 점을 확인하고 명시적 확인을 받는다. |
| QR 스캔 등 집중 작업 | Full Screen | 카메라 권한, 밝은 화면, 스캔 결과와 취소 동작에 집중할 수 있게 한다. |

데스크톱에서는 넓은 상세 패널을 보조적으로 사용할 수 있지만, 화면 책임과 행동 순서는 모바일 규칙을 기준으로 유지한다. 짧은 조치가 입력 항목 증가나 복잡한 판단을 요구하게 되면 Bottom Sheet에 계속 추가하지 않고 별도 Page로 승격한다.

### Bottom Sheet 동작

- Bottom Sheet는 목록 위에 overlay로 표시하며 목록 컴포넌트를 언마운트하지 않는다.
- 닫기 버튼, backdrop 탭, `Escape` 키(가능한 환경)를 제공한다. 위험 작업 중에는 먼저 확인 Dialog를 표시한다.
- Sheet가 열려 있는 동안 배경 스크롤은 잠그되, 닫으면 기존 목록의 스크롤 위치·검색어·필터·정렬·선택 맥락을 그대로 복원한다.
- Sheet 안에는 핵심 정보와 최대 2~3개의 빠른 액션만 둔다. `상세 보기`, `수정`처럼 더 긴 흐름으로 가는 명확한 진입점을 둔다.
- 모바일에서는 화면 하단에서 올라오고, 안전 영역(`safe-area inset`)과 키보드로 가려지지 않는 높이를 고려한다.

### Dialog 동작

- 위험 작업은 실행 버튼을 즉시 API 호출에 연결하지 않는다. Dialog에서 대상 이름, 실행 결과, 취소 가능 여부를 다시 보여 준다.
- 파괴적 실행 버튼은 위험 색상과 구체적인 동사(예: `김모임님 탈퇴 처리`)를 사용한다.
- 기본 포커스는 취소에 두고, 확인 후 성공하면 원래 목록/상세 맥락으로 돌아가 결과 메시지를 표시한다.
- 모달에서 본문과 분리해야 하는 주요·위험 행동은 재사용 가능한 footer 영역에 둔다. 본문만 스크롤되고 footer는 하단에 유지되어, 긴 상세에서도 실행 버튼을 잃지 않게 한다.

## 회원 흐름

회원은 다음 흐름을 표준으로 한다.

```text
회원 목록
  → 회원 선택 Bottom Sheet (핵심 정보, 상태, 빠른 액션)
    → 상세 보기 Page (이력·활동 제외 기간 등 복잡한 정보)
    → 수정 Page
  → 새 회원 등록 Page
탈퇴 / 재활성화
  → 확인 Dialog
```

- 목록 선택은 Bottom Sheet를 열며, 목록의 스크롤 위치·검색어·필터·정렬을 유지한다.
- 회원 역할은 이름 옆의 텍스트·아이콘 배지로 항상 표시한다. 모임장, 운영진, 회원의 배지는 색뿐 아니라 텍스트와 아이콘으로 구분하며, 기본 정렬은 모임장 → 운영진 → 회원, 같은 역할 안에서는 이름순이다.
- 회원 목록은 데스크톱에서 `회원 정보 | 미출석 상태`의 고정 grid 열을 사용한다. 활동 상태는 이름 바로 옆에 표시하고, 이름 길이와 무관하게 미출석 상태 열을 정렬한다.
- 정모 목록은 데스크톱에서 `날짜·제목 | 종류 | 출석 상태`의 고정 grid 열을 사용하며, 모바일에서는 종류와 출석 상태를 오른쪽 두 줄로 재배치한다.
- 새 회원 등록의 역할 선택은 세 가지 선택지를 한눈에 비교할 수 있는 배지형 라디오 버튼으로 제공한다. 네이티브 select의 옵션 색상·아이콘은 모바일과 브라우저마다 표현이 달라 역할 구분에는 사용하지 않는다.
- 역할 필터는 전체, 모임장, 운영진, 회원을 제공한다. 이 역할은 로그인 권한과 별개인 모임 내 직책임을 화면에서 혼동하지 않게 한다.
- Bottom Sheet의 빠른 액션은 `상세 보기`, `수정`, 상태에 맞는 위험 작업 진입으로 제한한다.
- 새 항목 등록과 기존 항목 수정은 별도 Page로 열고, 화면 제목과 주요 버튼을 각각 `회원 등록` / `변경사항 저장`처럼 작업에 맞게 명시한다.
- 활동 제외 기간처럼 여러 이력과 입력이 필요한 작업은 상세 Page 안에서 처리한다.
- 탈퇴, 숨김, 취소, 비활성화처럼 이력에 영향을 주는 작업은 반드시 Dialog 확인 단계를 둔다.
- 게스트 모드는 읽기 전용 안내를 항상 표시하고, 등록·수정·상태 변경·출석·쿠폰·QR 같은 변경 진입점을 숨긴다. 조회, 검색, 필터, 목록·상세 확인은 유지한다.

## 화면 전환 기준

| 작업 성격 | 권장 방식 | 예시 |
| --- | --- | --- |
| 짧은 단일 작업 또는 확인 | Bottom Sheet 또는 Dialog | 출석 처리, 쿠폰 사용 확인, 상태 변경 |
| 입력 항목이 많거나 작성 시간이 김 | 별도 Page | 회원 등록/수정, 회의록 작성/수정 |
| 목록에서 빠른 확인 | Bottom Sheet | 회원/쿠폰 핵심 정보와 빠른 액션 |
| 복잡한 이력·상세 판단 | 별도 Page | 회원 상세, 쿠폰 사용 이력, 회의록 상세 |

모바일에서는 좁은 가운데 모달보다 바텀시트 또는 전체 화면을 우선 검토한다. 긴 폼은 전체 화면으로 열어 스크롤과 모바일 키보드 동작을 단순하게 유지한다.

## 기능별 MVP 방향

- 회원: 목록 선택은 Bottom Sheet, 상세 조회는 별도 Page, 등록/수정은 별도 Page, 탈퇴/재활성화는 Dialog로 분리한다.
- 출석: 캘린더에서 날짜/모임을 선택하고, 출석 처리처럼 짧은 작업은 Bottom Sheet로 제공한다. 출석부 생성처럼 입력이 있는 작업은 별도 Page로 승격을 검토한다.
- 수업 개설 폼에서는 진행자를 선택할 수 있으며, 선택한 진행자는 개설과 동시에 진행자 출석으로 기록한다. 열린 출석부에 일반 회원을 추가할 때는 참여 방식 선택 없이 기본 출석으로 기록한다.
- 출석부 목록은 진행자를 최상단에 고정하고, 나머지 기록은 이름 오름차순으로 정렬한다. 진행자·일반 출석·쿠폰 사용은 서로 다른 색의 표기로 구분한다.
- 쿠폰: 목록 선택은 Bottom Sheet로 핵심 정보와 빠른 액션을 제공하고, 사용·정지·폐기·사용 취소는 Dialog 확인을 거친다. QR 사용은 Full Screen으로 연다.
- 회의록: 목록과 작성/수정을 분리한다. Markdown 편집은 별도 Page에서 제공하고, 상세 조회가 길어지면 별도 Page로 연다.

### 취소 이력

- 모임 취소는 사유 입력이 필수인 Dialog에서 확인한다. 취소 완료 후에는 기존 목록·캘린더에서 제외하고, 취소 이력 모달에서 날짜·모임명·사유를 페이지 단위로 조회한다.

### 공통 시각 시스템

- 전체 배경은 매우 연한 회색, 콘텐츠는 중앙 정렬된 적당한 최대 폭, 주요 정보는 흰색 Card로 구성한다.
- 색상·간격·모서리·그림자·글자 크기는 CSS design token으로 관리한다. 보라/인디고 primary는 현재 선택·주요 행동에만 사용하고, 나머지 동작은 중립 pill 버튼을 사용한다.
- `Button`, `Card`, `Chip`, `EmptyState`, `BottomNav`, `SelectField`를 공통 프리미티브로 제공한다. 새 화면은 우선 이 프리미티브를 사용하고, 기능별 스타일을 새로 하드코딩하지 않는다.
- 선택 필드는 브라우저 기본 select에 의존하지 않는다. 선택 버튼과 목록은 열린 상태에서 하나의 연결된 컨트롤처럼 보이게 하고, 목록의 선택 항목을 primary soft 색상으로 표시한다. Dialog·Bottom Sheet 안의 선택 목록은 portal 기반 floating layer로 표시해 부모 스크롤 영역에 잘리지 않으며, 화면 경계에서는 위쪽으로 열 수 있다.
- 빈 상태는 중앙의 단순 아이콘, 짧은 제목, 다음 행동을 안내하는 한 줄 설명으로 통일한다.
- 모바일에서는 BottomNav를 화면 하단에 고정한다. 본문에는 safe area와 BottomNav 높이만큼의 여백을 두며, 데스크톱에서는 pill 형태의 상단 메뉴를 사용한다.
- 날짜 입력은 `YYYY/MM/DD` 순서의 공통 텍스트 입력을 사용한다. 클릭하면 앱의 작은 달력으로 선택할 수 있고 직접 입력도 가능하며, API에는 ISO `YYYY-MM-DD`로 전달한다.
- 캘린더의 날짜 선택은 숫자에만 작은 터치 대상을 두지 않고 칸 전체에서 가능하게 한다. 칸 안의 개별 모임 버튼은 날짜 선택과 별도의 상세 진입점으로 유지한다.
- 캘린더의 앞·뒤 빈 칸은 이전·다음 달의 실제 날짜로 채운다. 보조 달 날짜를 누르면 해당 달로 이동해 그 날짜를 선택하며, 해당 날짜의 모임도 동일하게 표시·진입할 수 있어야 한다.
- 정모는 수업과 행사로 구분해 색과 텍스트 배지를 함께 사용한다. 행사는 시작일과 종료일을 입력하고, 기간의 모든 날짜에서 동일한 정모 상세로 진입할 수 있게 표시한다.
- 캘린더의 연·월 조작은 제목 아래 중앙 행에 배치한다. 이전·다음 달은 그림자 없는 `<`·`>` 아이콘 버튼으로 제공하고, 표시된 연·월을 누르면 연도 이동과 월 선택을 함께 제공하는 작은 팝오버를 연다.
- 활동 중인 회원은 마지막 유효 출석일을 기준으로 1개월, 2개월, 3개월 이상 미출석 배지를 목록에 표시한다. 취소된 출석·취소된 모임·미래 모임은 계산에서 제외한다. 출석 이력이 없는 활동 회원은 가입 후 3개월 전까지 `🌱 새싹 회원`, 이후에는 `미활동자` 배지를 표시하며, 탈퇴 회원에게는 표시하지 않는다.

## 리팩터링 시점

기능 개발 중에는 사용 흐름을 막는 UX 문제를 즉시 고친다. 새 화면이나 기존 화면 변경 시에는 이 문서의 작업 성격 표를 먼저 적용한다. 현재 구현처럼 등록·상세·수정이 한 화면 패널에 공존하는 흐름은 횡단 UI/UX 리팩터링에서 회원 흐름부터 위 기준으로 전환한다. 공통 Bottom Sheet, Dialog, Page 전환, 상태 배지, 터치 대상, 메뉴 구조는 재사용 가능한 규칙으로 함께 정리한다.

## 게시판 관리 흐름

- 게시판 기본 화면은 카테고리 필터·정렬·게시글 목록만 제공한다. 글 작성과 기존 글 수정은 별도 Page로 이동하며, 편집 Page에서 Markdown 미리 보기를 제공한다.
- 카테고리 생성·수정·비활성화는 일반 게시판 흐름에서 분리한 관리자 전용 설정 Page에 둔다. 게스트에게는 설정 진입점을 노출하지 않으며 서버는 변경 API를 `ADMIN`으로 제한한다.

## 쿠폰 관리 흐름

- 쿠폰 관리의 기본 화면은 쿠폰 목록과 후속 작업에 집중한다. 수동 쿠폰 발급은 목록 헤더의 `쿠폰 발급` 버튼으로 별도 Page 형태의 입력 화면에 진입한다.
- QR은 현재 QR을 유지하는 `QR 보기`와 기존 QR을 무효화하는 `QR 재발급`을 분리한다. QR 생성·표시는 집중 작업이므로 Full Screen으로 제공한다.
- 출석왕 자동 발급은 대상 월만 지정하는 짧은 작업이므로 목록 위 패널 대신 Dialog로 제공한다. 한글 연도·월 선택을 사용하고, 월을 바꾸면 해당 월의 기존 수상 결과를 자동 조회한다. 이 목록에서는 확정된 수상자에게만 `수상 취소`를 직접 제공한다. 출석왕 쿠폰을 쿠폰 목록에서 열면 `⋮` Bottom Sheet에서도 동일한 수상 취소를 제공한다.
- 취소된 출석왕 수상은 자동 발급 목록과 해당 쿠폰의 `⋮` Bottom Sheet에서 `수상 복원`으로 되돌릴 수 있다. 이미 사용한 쿠폰이 있으면 복원하지 않는다.
- 출석 기록 후에는 회원 검색 선택을 초기화한다. 자동완성은 단일 해제 버튼과 키보드 위·아래 이동 및 Enter 선택을 제공한다.
- 출석부에 이미 있는 회원을 다시 선택해 참여 방식을 바꾸려 하면 확인 Dialog를 먼저 표시한다. 확인하면 기존 기록을 새로 만들지 않고 참여 방식만 바꾸며, 취소된 기록은 선택한 참여 방식으로 출석을 다시 기록한다. 취소된 출석은 버튼형 배지 대신 붉은 `취소` 텍스트와 취소 사유로 구분한다.
- 쿠폰 출석의 취소는 일반 출석 취소 API를 사용하지 않고, 연결된 쿠폰 사용과 출석 기록을 한 트랜잭션으로 되돌린다.
- 이미 개설한 정모는 취소 이력이 아닌 경우 상세 Dialog의 `정모 정보 수정`에서 날짜·진행자·제목·장소를 수정할 수 있다.
- 출석부 목록은 기본적으로 `출석 진행 중`만 보여 주고, `전체`·`출석 진행 중`·`마감` pill 버튼으로 필터를 전환한다. 마감된 출석부는 `재개` 후 출석을 수정하고 다시 마감할 수 있다.
- 모든 Dialog는 닫기 버튼과 `Escape` 키로 닫을 수 있으며, 긴 내용은 둥근 외곽을 유지한 내부 영역에서 스크롤한다.
- 쿠폰 목록은 쿠폰 이름 아래에 `대상자 이름 · 잔여 n회`, 그 아래에 쿠폰 기한만 차례로 보여 빠르게 읽도록 한다. 상태는 pill 필터(`전체`, `사용 가능`, `정지`, `사용 완료`, `만료`, `폐기`)와 배지로 구분한다. 사용 가능 쿠폰은 QR이 있으면 `QR 보기`, 없으면 `QR 발급`과 `쿠폰 사용`만 직접 노출한다. 나머지 작업은 `⋮` Bottom Sheet에서 제공하며, 수동 쿠폰의 폐기는 확인 Dialog를 거치고 미사용 폐기 쿠폰은 Bottom Sheet에서 폐기를 취소할 수 있다. 사용과 사용 이력은 목록 아래에 펼치지 않고 Dialog로 연다. 수동 발급 때 입력한 쿠폰 이름은 목록 제목으로 표시한다.
- 쿠폰 상태 배지는 영속 상태와 날짜 기반 표시 상태를 함께 반영한다. 사용 가능 상태라도 기한이 지나면 `만료`로 표시하고, 만료 쿠폰에는 사용·QR 발급 같은 사용 가능 액션을 노출하지 않는다.
