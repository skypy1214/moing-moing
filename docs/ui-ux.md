# UI/UX 원칙

## 목적

이 문서는 소모임 운영진용 관리자 화면의 일관된 사용 경험을 위한 기준이다. 현재 사용자는 적고 관리 작업은 반복되므로, 화려한 화면보다 실수 예방과 작업 상태의 명확성을 우선한다.

## 반응형 기본 원칙

- 데스크톱과 모바일 모두 지원한다. 좁은 화면에서는 다열 레이아웃을 한 열로 전환한다.
- 모바일에서 모든 기능을 작은 모달에 넣지 않는다. 키보드가 열려도 입력 흐름이 유지되어야 한다.
- 버튼과 입력 요소는 터치 가능한 크기를 확보하고, 위험 작업은 일반 작업과 시각적으로 구분한다.

## 등록과 상세/수정의 구분

- 새 항목 등록, 기존 항목 상세 조회, 기존 항목 수정은 같은 의미로 보이지 않게 한다.
- 화면 제목과 주요 버튼을 각각 `회원 등록` / `변경사항 저장`처럼 작업에 맞게 명시한다.
- 목록에서 선택한 기존 항목은 상세 모드로 열고, `새로 등록`을 명시적으로 선택했을 때만 등록 모드로 전환한다.
- 탈퇴, 숨김, 취소, 비활성화처럼 이력에 영향을 주는 작업은 별도 위험 영역 또는 확인 단계에 둔다.

## 화면 전환 기준

| 작업 성격 | 권장 방식 | 예시 |
| --- | --- | --- |
| 짧은 단일 작업 또는 확인 | 모달 또는 모바일 바텀시트 | 출석 처리, 쿠폰 사용 확인, 상태 변경 |
| 입력 항목이 많거나 작성 시간이 김 | 별도 전체 화면 | 회원 등록/수정, 회의록 작성/수정 |
| 목록에서 빠른 확인과 소규모 수정 | 데스크톱 상세 패널, 모바일 상세 화면 | 회원/쿠폰 상세 |

모바일에서는 좁은 가운데 모달보다 바텀시트 또는 전체 화면을 우선 검토한다. 긴 폼은 전체 화면으로 열어 스크롤과 모바일 키보드 동작을 단순하게 유지한다.

## 기능별 MVP 방향

- 회원: 목록과 상세를 분리한다. 등록과 수정은 명확히 구분된 화면 또는 전체 화면 폼을 사용한다.
- 출석: 캘린더에서 날짜/모임을 선택하고, 출석 처리처럼 짧은 작업은 모달 또는 바텀시트를 사용한다.
- 쿠폰: 목록 중심으로 제공하고 사용, 정지, 연장 같은 짧은 조치는 확인 모달/바텀시트를 사용한다.
- 회의록: 목록과 작성/수정을 분리한다. Markdown 편집은 충분한 폭의 전체 화면 또는 넓은 편집 화면을 사용한다.

## 리팩터링 시점

기능 개발 중에는 사용 흐름을 막는 UX 문제를 즉시 고친다. 회원·출석·쿠폰·회의록의 실제 DB 연동이 안정된 뒤에는 공통 버튼, 입력, 패널, 모달/바텀시트, 상태 배지, 메뉴 구조를 함께 정리하는 UI 리팩터링 단계를 진행한다.
