# 중요 미결정 사항

이 문서는 구현 결과를 크게 바꿀 수 있는 질문을 추적한다. 결정하면 상태를 `결정`으로 바꾸고 날짜, 선택, 근거를 적은 뒤 요구사항/도메인/아키텍처에도 반영한다.

## 구현 전 우선 결정

### OQ-01 인증 방식과 운영자 역할

- 상태: 미결정
- 결정 시점: Phase 1 말, Phase 2 시작 전
- 질문: 로컬 계정+세션과 GitHub/Google OIDC 중 무엇을 쓰며, `ADMIN` 단일 역할로 충분한가?
- 제안: 동일 origin Spring Security 세션 인증을 기본으로 하고, 운영진이 공유하는 계정 공급자가 명확하면 OIDC를 비교한다. 운영 환경의 인증 생략은 허용하지 않는다.

### OQ-02 회원 생명주기와 재가입

- 상태: 미결정
- 결정 시점: Member migration 작성 전
- 질문: 탈퇴 후 재가입한 사람을 기존 Member 재활성화로 볼지 새 가입 기간/새 Member로 볼지, 동일인 판별 키는 무엇인가?
- 제안: 이름/닉네임만으로 자동 병합하지 않는다. 재가입 이력이 중요하면 `MembershipPeriod` 도입도 검토한다.

### OQ-03 활동 제외 기간

- 상태: 일부 결정
- 결정 시점: Member migration 작성 전
- 결정(2026-08-19): `MemberActivityExclusion(startDate, endDate, reason)`로 관리하며 `endDate = null`인 무기한 활동 중단을 허용한다. 복귀 시 종료일을 기록하고 기간 중첩은 금지한다.
- 남은 질문: 월 일부만 제외된 회원을 활동률에서 어떻게 계산하는가?
- 제안: 월 인정 기준은 별도 통계 정책으로 두고 Phase 4 전에 예시 데이터로 확정한다.

### OQ-04 출석부 단위

- 상태: 미결정
- 결정 시점: Gathering migration 작성 전
- 질문: 하루에 여러 모임이 가능한가? 시간, 장소, 취소/마감이 필요한가?
- 제안: `Gathering` 엔티티를 두고 하루 여러 건을 허용할 수 있게 설계하되, 실제 UI는 날짜 중심으로 단순하게 시작한다.

### OQ-05 출석 기록 정정

- 상태: 미결정
- 결정 시점: Attendance migration 작성 전
- 질문: 잘못된 출석을 물리 삭제할지 취소 이력으로 남길지, 쿠폰 사용 출석 취소 시 쿠폰을 자동 복원할지?
- 제안: 유효/취소 상태와 수행자·사유를 남기며, 쿠폰 사용 취소와 복원은 한 트랜잭션의 명시적 유스케이스로 만든다.

### OQ-06 월간 통계의 대상 회원

- 상태: 미결정
- 결정 시점: Phase 4 시작 전
- 질문: 월초/월말/월중 어느 시점의 회원을 분모로 보는가? 월중 가입·탈퇴자는 어떻게 하는가?
- 제안: 임의의 월말 스냅샷보다 가입일/탈퇴일과 월의 교집합으로 대상자를 산정하고 상세 대상을 함께 표시한다. 최종 업무 규칙은 운영진이 예시 데이터로 승인해야 한다.

### OQ-07 활동률 공식

- 상태: 미결정
- 결정 시점: Phase 4 시작 전
- 질문: `(출석자 + 활동 제외자) / 대상자`에서 두 집합 중복을 어떻게 처리하며, 일부 기간 제외도 한 명으로 인정하는가?
- 제안: 합집합으로 중복을 제거한다. 정책 버전과 예시(가입, 탈퇴, 월 일부 휴식, 출석 후 휴식)를 먼저 표로 확정한다.

### OQ-08 출석왕 동률과 자격

- 상태: 일부 확정
- 확정: 1명 또는 공동 1등 2명은 각 2회 무료. 무료/쿠폰 출석은 제외.
- 질문: 공동 1등 3명 이상, 0회인 달, 최소 횟수, 월중 탈퇴자의 수상 자격은?
- 결정 시점: 출석왕 로직 구현 전
- 제안: 자동 발급을 보류하고 관리자에게 후보와 사유를 보여 수동 확정하도록 한다. 0회인 달은 수상자 없음으로 한다.

### OQ-09 출석왕 확정과 재계산

- 상태: 미결정
- 결정 시점: Phase 4 시작 전
- 질문: 월 마감 후 과거 출석 정정 시 수상/이미 사용된 보상을 어떻게 처리하는가?
- 제안: 계산 미리보기와 관리자 확정을 분리하고 확정 결과에 정책 버전/횟수를 저장한다. 확정 후 정정은 자동 회수하지 않고 별도 보정 절차를 둔다.

### OQ-10 쿠폰 단위와 사용 모델

- 상태: 미결정
- 결정 시점: Coupon migration 작성 전
- 질문: 2회 보상을 2장의 1회권으로 발급할지, 2회 잔액 쿠폰 한 장으로 발급할지? 부분 사용/양도/사용 취소를 허용하는가?
- 제안: `Coupon` 1:N `CouponUsage`로 양쪽을 수용하되, MVP UX는 2회 잔액 한 장 또는 1회권 두 장 중 하나로 고정한다.

### OQ-11 쿠폰 만료와 삭제

- 상태: 미결정
- 결정 시점: Phase 5 시작 전
- 질문: 만료를 날짜로 계산할지 상태로 저장할지, 미사용 오발급의 물리 삭제를 허용할지?
- 제안: 만료는 날짜에서 계산하고 오발급은 `VOIDED` 처리한다. 물리 삭제는 운영 데이터에서 허용하지 않는다.

### OQ-12 QR 보안과 공개 범위

- 상태: 미결정
- 결정 시점: Phase 6 시작 전
- 질문: QR 링크를 로그인 사용자만 열 수 있는가? 회원이 QR을 보관/공유할 수 있는가? 토큰 회전이 필요한가?
- 제안: QR 조회와 사용 모두 인증된 운영자만 수행한다. QR에는 랜덤 토큰만 넣고 서버에는 해시를 저장하며, 스캔만으로 즉시 사용되지 않게 확인 단계를 둔다.

## 후속 결정

### OQ-13 외부 명부 스크린샷 동기화

- 상태: 미결정
- 결정 시점: MVP 이후
- 질문: 지원 이미지/언어/레이아웃, OCR 처리 위치, 개인정보 보존, 이름 충돌과 사람 승인 흐름은?
- 제안: OCR 결과를 즉시 반영하지 않고 현재 명부와 비교한 가입/탈퇴 후보를 운영자가 승인하게 한다. 외부 API 제공 여부도 먼저 확인한다.

### OQ-14 Markdown 정책

- 상태: 미결정
- 결정 시점: Phase 7 시작 전
- 질문: raw HTML, 외부 이미지/링크, 첨부파일, Mermaid 등을 허용하는가?
- 제안: MVP는 raw HTML과 임의 스크립트를 금지하고 요구된 CommonMark/GFM 요소만 안전하게 렌더링한다.

### OQ-15 회의록 삭제와 수정 이력

- 상태: 미결정
- 결정 시점: Phase 7 시작 전
- 질문: 숨김 복구, 영구 삭제 권한, 버전 비교가 필요한가?
- 제안: 숨김과 복구를 제공하고 영구 삭제/Revision은 실제 요구가 확인될 때 추가한다.

### OQ-16 배포, 백업, 개인정보

- 상태: 미결정
- 결정 시점: Phase 8 이전
- 질문: 배포 공급자/도메인/예산/리전, 백업 주기와 보존 기간, 회원 데이터 삭제 요청 대응은?
- 제안: 무료 티어만을 목표로 데이터 안전성을 낮추지 않는다. 관리형 PostgreSQL 또는 검증된 자동 백업을 선택하고 복구 리허설을 완료 조건으로 둔다.

### OQ-17 오픈소스 라이브러리 선정

- 상태: 미결정
- 결정 시점: 각 의존성 도입 직전
- 질문: QR 생성/스캔, Markdown 렌더링/편집, 보안 sanitization 라이브러리는 무엇인가?
- 평가 기준: OSI 계열 라이선스와 상업적 무료 사용 가능성, 최근 유지보수, 보안 이력, 번들 크기, 브라우저 지원, 접근성, 대체 가능성. 선택 결과와 라이선스를 의존성 결정 기록에 남긴다.
