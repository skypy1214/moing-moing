# 이벤트 역할 선택 정책

## 화면 흐름

- 이벤트 탭은 게시판과 같은 목록 화면이다. 관리자는 우측 상단의 `이벤트 생성`으로 별도 생성 화면에 들어간다.
- 목록의 이벤트를 누르면 별도 상세 화면의 좌석표로 이동한다.
- 생성과 수정은 하나의 편집 화면을 공유한다. 편집 화면에서 이벤트명, 상태, 역할명과 역할 안내를 관리한다.
- 이벤트 삭제는 논리 삭제(`DELETED`)이며 목록에서만 숨긴다. 역할 삭제는 물리 삭제다.

## 좌석 배치

- 역할 생성 순서가 좌석 순서다.
- 한 분단은 2열 × 5행, 총 10개 역할이다. 다음 10개 역할은 간격을 둔 다음 분단에 표시한다.
- 좌석에는 역할명과 선택 가능 여부만 표시한다. 빈 역할을 누르면 확정 전 역할 설명을 확인할 수 있다.

## 권한과 확정

- 일반 사용자는 `OPEN` 상태 이벤트만 목록과 상세 화면에서 조회할 수 있다.
- 역할 설명은 선택 전 확인을 위해 공개한다. 미션은 확정한 본인과 운영진(`ADMIN`, `SITE_ADMIN`, `GROUP_LEADER`, `STAFF`)에게만 응답한다. 운영진은 역할 상세 모달의 `미션 확인` 버튼으로 열람하며, 일반 회원에게는 다른 역할의 미션 필드 자체를 반환하지 않는다.
- 역할 확정은 이벤트당 사용자 1개, 역할당 사용자 1개라는 DB 고유 제약을 사용한다. 삽입은 `ON CONFLICT DO NOTHING`으로 처리해 동시 요청에서도 한 명만 성공한다.
- 일반 사용자의 역할 변경은 지원하지 않는다. 관리자는 아직 확정되지 않은 역할의 이름·설명·미션을 수정할 수 있다. 확정 기록이 있으면 서버가 수정을 거부한다.
- 역할을 삭제하면 해당 역할에 연결된 선택 기록도 함께 물리 삭제된다. 이미 확정된 역할을 지우는 것은 관리자만 예외 처리용으로 수행한다.

## 마이그레이션

초기 프로토타입(V21/V22)의 좌석 행·열 모델은 V23에서 이벤트 테이블만 재생성해 `display_order` 모델로 전환했다. V23 적용 시 기존 이벤트·역할·선택 데이터는 삭제된다. 다른 도메인 테이블에는 영향을 주지 않는다.
